#FRTB & Model Validation (Regulatory Capital, Independent Validation)

An educational implementation of the Basel FRTB (Fundamental Review of the
Trading Book) market-risk capital mechanics in four languages, on a small
self-contained two-desk portfolio. It computes the Standardised Approach —
Sensitivities-Based Method (GIRR / equity / FX delta, vega and curvature,
three correlation scenarios, the S_b fallback rule), a DRC-lite Default Risk
Charge with issuer netting and the hedge benefit ratio, and the Residual Risk
Add-On — alongside an Internal Models Approach sketch (97.5% Expected
Shortfall with the liquidity-horizon ladder, IMCC, 99% VaR backtesting zones
and multipliers, the P&L attribution test with an Amber surcharge, and NMRF
stress capital). On top sits an independent model-validation framework
(SR 11-7 flavour): pricing benchmark against a binomial lattice, delta vs
finite differences, capital stability under risk-weight perturbation, data
quality, a pinned findings rule table and an auto-generated
`validation_report.md`. The teaching document [LEARN.md](LEARN.md) explains
every formula; [COOKBOOK.md](COOKBOOK.md) has copy-paste recipes in all four
languages; [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) covers design and
numerics.

> **EDUCATIONAL PARAMETER SET — NOT A COMPLIANT CAPITAL ENGINE.**
> Every risk weight, correlation, bucket set and threshold is a pinned,
> Basel-2019-flavored *teaching* value: simplified bucket structure, no
> securitisations, a subset of risk classes, and several documented formula
> simplifications (see LEARN.md §10 and API_SPEC.md). Never use this code or
> its parameters for real regulatory capital.

## Feature matrix

| Feature | Notes |
|---|---|
| SBM risk classes | GIRR (10 curve tenors, USD + EUR), equity (Basel buckets 1–4 + 11, pinned RWs), FX (single pinned bucket, RW 15%) |
| SBM measures | Delta, vega (equity only in the bundled book; GIRR vega structurally 0, FX vega not modelled), curvature (CVR± with ψ) |
| Aggregation | `K_b = sqrt(max(0, ΣWS² + Σρ WS WS))` within bucket, `γ_bc`·S_b·S_c across buckets with the FRTB S_b fallback rule |
| Correlation scenarios | high `min(1.25ρ, 1)`, medium `ρ`, low `0.75ρ` (pinned simplification); SBM capital = max of the three totals |
| Curvature | Full-RW up/down shocks, delta term stripped; ψ both-negative rule at both levels; `ρ_curv = ρ_scen²`, `γ_curv = γ_scen²` (pinned) |
| Sensitivities | Pinned bump-and-revalue: GIRR +1bp per node, equity/FX +1% relative spot, vega +1 vol pt (WS uses `vega·σ`); full-portfolio revaluation per bump |
| Pricers | Bullet bond, payer-swap proxy, Black–Scholes with dividend yield (T=0 / σ=0 edge cases), FX forward, CRR binomial benchmark (501 steps) |
| DRC-lite | `JTD = LGD·N + (MV − N)`, same-issuer netting, HBR weighting of net shorts, rating RW table (AAA 0.5% … D 100%), bonds only |
| RRAO | Flagged notionals × pinned rates: exotic 1.0%, other 0.1% |
| IMA ES | Daily 97.5% ES (k = 7 worst of 260), √10 scaling to 10d, liquidity-horizon ladder (10/20/40/60/120d; ir/eq→20, fx→40, cr→60) |
| IMCC | `0.5·ES_LH(full) + 0.5·Σ ES_LH(category)`; capital = multiplier·IMCC + SES (static-portfolio simplification documented) |
| Backtesting | 99% VaR exceptions (`PnL < −VaR`), Basel zones green 0–4 / amber 5–9 / red ≥10, pinned multiplier table 1.50 → 2.00 |
| PLAT | Native Spearman (average ranks) + exact two-sample KS; green/amber/red with pinned thresholds (0.85/0.80, 0.09/0.12); Amber surcharge `0.5·max(0, SA − IMA_core)`; constant-P&L → Red |
| NMRF / SES | Sum of pinned stressed losses, zero diversification |
| Validation | BS vs binomial benchmark grid (40 prices, tol 0.05), delta vs central FD (tol 1e-6), ±10% GIRR RW stability, staleness/gap data quality, findings rule table (High/Medium/Low), verdict approve / approve-with-conditions / reject, full markdown report generator |
| Portfolio | desk1 rates (3 bonds + payer swap), desk2 equity/FX (3 options incl. one short, FX forward, high-yield bond for DRC) |
| Determinism | No RNG at runtime; the only seeded RNG (seed 20250815) lives in `data/generate_data.py` |
| Cross-language tests | 21 golden cases in `data/golden/golden.json` (tolerances 1e-8 … 1e-12; zones and verdicts exact strings) |

## Build / run / test

### Python (reference)

```bash
cd python
PYTHONPATH=src python3 demo.py       # end-to-end capital + validation report
PYTHONPATH=src pytest -q             # test suite (111 tests)
```

### C++

```bash
cd cpp
./build.sh                           # cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j2
./build/demo                         # demo
ctest --test-dir build --output-on-failure
```

### Rust

```bash
cd rust
cargo build --release
cargo run --release --bin demo
cargo test
```

### Java

```bash
cd java
./build.sh                           # javac everything into out/
./demo.sh                            # runs the demo main
./test.sh                            # JUnitCore on all *Test classes
```

## Golden values — cross-language testing

`data/golden/golden.json` holds 21 named reference cases produced by the
Python implementation on the bundled data (plus one hand-derived 2-bucket
aggregation example checked analytically before anything else is written).
The schema is flat and easy to parse in every language:

```json
{ "cases": [ { "name": "girr_kb_usd",
               "inputs": { "scope": "firm", "scenario": "medium" },
               "expect": { "kb": 413453.9738180512 },
               "tol": 1e-08 } ] }
```

Every language's test suite loads this file and asserts agreement within
`tol` — numeric values at 1e-8 to 1e-12, zone and verdict strings exactly.
Covered: per-tenor GIRR weighted sensitivities, within-bucket K_b (GIRR and
equity), the three SBM scenario totals and final capital, per-desk SBM
capitals, the equity curvature charge, DRC and HBR, RRAO, base and LH-scaled
ES per desk, IMCC, PLAT metrics and zones, backtest exception counts and
multipliers, SES, the pricing-benchmark max diff, the +10% GIRR RW stability
delta, and both desks' validation verdicts. Because the whole pipeline is
deterministic (no runtime RNG), any cross-language discrepancy is a real
porting bug, not noise.
